SMS | Reporting Guide

Dashboard Reports
& Metrics

How to use and interpret the admin/staff dashboard's filters, summary cards, enrollment charts, course totals, and recent activity.

Dashboard: /dashboard

Controller: DashboardController@index

Audience: Active admin/staff accounts with verified email

1. Report scope

The reporting feature is an interactive dashboard rendered as a web page. It summarizes normalized student enrollment records, enrollment status, monthly activity, and course totals. It is not a separate analytics API or a downloadable spreadsheet/PDF export function.

No export endpoint is currently defined. The dashboard provides on-screen cards, charts, and tables; the application does not expose report CSV, Excel, or PDF download routes in the reviewed route set.

2. Access and navigation

Open /dashboard after signing in as an active administrator or staff member with verified email. The root route sends staff/admin users to the staff dashboard and students to the student portal. Students do not have access to the aggregate dashboard; they see their own enrollment history on /student/dashboard.

3. Dashboard filters

Query parameterAccepted valuesDefault and effect
yearInteger from 1900 through next calendar year.Defaults to current year; scopes the reporting date window.
monthall or 1 through 12.Defaults to all months; narrows enrollment and activity counts to a month when selected.
statusall or a status present in the enrollment table; pending and approved are always included as choices.Defaults to all statuses; filters enrollment-related metrics by status.

Filters are submitted as GET parameters, so the selected view can be bookmarked or shared with authorized users. “Reset filters” returns to the default view.

/dashboard?year=2026&month=11&status=pending

Charts are rendered in the browser with Chart.js. The server supplies twelve month labels and aligned count arrays. Database-specific date expressions are selected for SQLite, PostgreSQL, or MySQL-compatible drivers.

6. Interpretation and data definitions

  • Dashboard enrollment metrics use the normalized student_enrollments table, not the legacy enrollments table.
  • Enrollment period filtering uses enrollment_date; request activity uses created_at.
  • School year (for example 2026-2027) is an academic grouping field, separate from calendar year/month dashboard filters.
  • A student's global enrolled/unenrolled status is based on whether any normalized enrollment relation exists, regardless of selected period.
  • Pending and approved card metrics are computed for the selected time window; the status selector affects the main filtered result and related chart/table totals.
  • Charts represent current database values and are recalculated per dashboard request; there is no separate report snapshot or export archive.

7. Student report view

The student portal is a personal academic-history view, not an administrative aggregate report. It displays the signed-in student's linked profile, enrollment groups by school year, course/year placement, subject list, units, and statuses. Students can cancel their own pending enrollment requests. The page does not display other students' records or system-wide totals.

8. Operational notes and limitations

  • Counts may differ between global cards and period charts because only enrollment-specific metrics are period-filtered.
  • Recent activity is limited to 8 rows; use the enrollment-management page for full searchable/filterable history.
  • The dashboard does not provide CSV/Excel/PDF export, saved filters, scheduled reports, or historical snapshots.
  • For external reporting, apply appropriate privacy controls and least-privilege access before exporting student data.

9. Verification and source files

Dashboard functionality is covered by feature tests for displayed metrics, charts, filters, and recent records. Useful commands:

php artisan route:list --path=dashboard
php artisan test --filter=DashboardTest
