Student Management
System

Setup instructions, application features, user roles, and operational commands for the Laravel student management application.

Framework: Laravel 12, PHP 8.2+

Web: Role-based staff/admin tools and student portal

API: Sanctum-protected student resource endpoints

About

The Student Management System manages student profiles, courses, year levels, subjects, school-year enrollments, and enrollment approval. Staff and administrators use the management dashboard; students manage their own profile and enrollment requests.

Features

  • Admin/staff CRUD management for students, courses, year levels, subjects, and enrollments.
  • Student profile and enrollment self-service.
  • Approval and cancellation workflows that retain enrollment history.
  • Role-based user management.
  • Dashboard date/status filters, enrollment statistics, charts, course counts, and recent activity.
  • Sanctum student JSON API.

Requirements

  • PHP 8.2+, Composer, Node.js/npm, and a Laravel-supported database.

The example environment uses SQLite. Set up MySQL or another supported database in .env if desired.

Install and run

composer install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
php artisan key:generate
npm install
if (!(Test-Path database\database.sqlite)) { New-Item -ItemType File -Path database\database.sqlite }
php artisan migrate --seed
npm run build
php artisan storage:link
php artisan serve

Run npm run dev in a separate terminal while developing frontend assets. Configure the local database and application URL in .env. Never commit production credentials or the local environment file.

Initial administrator

The default database seeder creates test@example.com. Promote an existing local account with:

php artisan users:make-admin test@example.com

This makes the account an active administrator. Only run it for an account you control.

Roles and primary pages

  • Admin: Academic management and user access management.
  • Staff: Academic management and staff dashboard.
  • Student: Own student profile and enrollment portal.

Protected routes require an active account; the staff dashboard also requires verified email. New self-registered users start inactive pending administrator approval.

Testing

Use a disposable test database. PHPUnit does not force a test database in this project, so tests may otherwise connect to the database selected in .env.
php artisan test

Focused examples: php artisan test --filter=StudentApiTest and php artisan test --filter=EnrollmentTest.

PHPUnit uses an in-memory SQLite database by default; feature tests refresh their schema. Explicit environment overrides should point only to a disposable test database.
